# ADR 0001: 描画構成 — ELK.js の配置を Three.js で描く

日付: 2026-10-23
状態: 採用

## 決定

- 自動配置は **ELK.js**（`layered`、階層ごとに独立して計算）。
- 描画は **Three.js（WebGL）＋ CSS2DRenderer による DOM ラベル**。
- Cytoscape.js は採用しない。

## 検証したこと

同じサンプル（`samples/math.v1.json`、37 ノード、42 関係、最大 4 階層）で二つのスパイクを作り、
Playwright（Chromium、1280×800、Apple Silicon）で操作とスクリーンショットを取った。
スパイクは `spikes/` に残してあり、`npm run dev` 後に `/spikes/cytoscape-elk/` と `/spikes/elk-three/` で開ける。

### A: Cytoscape.js 3.34 + cytoscape-elk 2.3 + elkjs 0.12

| 項目 | 結果 |
| --- | --- |
| compound nodes で全階層を一枚に描く（`hierarchyHandling: INCLUDE_CHILDREN`） | 動く。配置 125ms。階層越えの辺も描ける |
| ELK 直接呼び出しと Cytoscape 上の位置 | 一致した（ELK の子座標は親の左上からの相対。cytoscape-elk が絶対座標に直している） |
| ELK のエッジ経路 | 反映されない。31 本に折れ点があったが、Cytoscape は自前の bezier で描く。階層越えの辺は ELK では共通祖先の座標系で返る |
| ラベル | ノード寸法にラベルが含まれず、全体表示で重なる。空の分野が隣のラベルと衝突した |
| 視点移動 | `cy.animate` の `ease-out-expo` で中央寄せ・ズームは滑らか |
| ダイブ | 「ズーム → 要素を差し替え → 子を親の位置から広げる」で成立はする。ただしビューポートは全体で一つなので、親と子を異なる縮尺で同時に置けず、切り替えは差し替えになる |
| 奥行き・発光 | 透視投影はない。`underlay` で発光風にはできるが、前後関係・視差は作れない |
| 依存関係 | cytoscape-elk の peerDependencies は `elkjs ^0.9.3`。0.12 でも動いたが範囲外 |

### B: elkjs 0.12 → Three.js 0.186 + CSS2DRenderer

| 項目 | 結果 |
| --- | --- |
| 配置 | 階層ごとに 15〜29ms（メインスレッド、bundled 版） |
| ダイブ | 子階層を親ノードの球の内側に縮尺 k（約 0.05）で置き、カメラ距離を対数空間で補間して近づく。親の消失と子の出現をカメラ距離から決めるので、途中で戻しても見た目が一貫する。到着時に子フレームを基準へ置き直し（rebase）、浮動小数の誤差をためない |
| 戻る | 親フレームを逆の縮尺で外側に作り、保存したカメラ位置へ引く。選択も復元できた |
| ラベル | DOM なので日本語が鮮明。縮尺はフレームの縮尺とカメラ距離から毎フレーム計算する必要がある |
| 奥行き・発光 | 透視、星空の視差、加算合成の発光、浮遊・呼吸が素直に書ける。待機時 約 60fps |
| ELK の経路 | `SPLINES` の `bendPoints` は折れ点ではなく三次ベジェの制御点。Catmull-Rom に通すと不自然な折れが出たので、ベジェとして組み立て直す必要がある |

スパイク中に見つけた注意点:

- 新しい基準フレームを二重に座標変換する不具合を一度入れた。rebase の対象は重複なく扱う。
- ease-out-expo で対数距離を補間すると、最初の 150ms で行程の約 7 割が終わり、接近が見えない。ダイブには緩い ease-out（cubic/quart）を初期値とし、`tuning.ts` で比較する。

## 判断の理由

求める体験の核は「ノードへ吸い込まれ、その中に次の世界が現れる」連続性と奥行き。
A は 2D のパン・ズームとしては完成度が高いが、親と子を異なる縮尺で同時に置けないため、ダイブが差し替えになる。
透視や視差を載せるには Cytoscape の描画を迂回することになり、ライブラリを使う利点が残らない。
B は配置（ELK）と描画を分けたまま、世界の中の世界を一つのシーンで表現できる。

編集との相性: どちらも意味モデルから毎回表示グラフを作るため差はない。B ではノードの追加・削除のたびにその階層の ELK 計算をやり直す（数十 ms）。

保守性: B は描画・ヒットテスト・ラベル配置を自前で持つ分、コードは増える。描画層を `src/scene` に閉じ込め、意味モデル・表示グラフ・レイアウト・遷移状態から独立させる。

## 帰結

- `hierarchyHandling` による全階層同時レイアウトは使わない。一度に描くのは現在の階層と、遷移中の隣接階層だけ。
- ELK は前提関係だけで層を決める。関連リンクは配置を縛らない。
- ELK の計算は Web Worker に移し、構造が同じならキャッシュを使う。
- 大規模ツリー（数百ノード／階層）での性能は未検証。
