# 交換フォーマット v1

ツリーの正本は意味情報だけを持つ JSON。座標、カメラ、描画ライブラリの ID、個人の学習記録は含めない。
定義は `src/model/schema.ts`（zod）で、`npm run schema` で `schema/skilltree.v1.schema.json` を生成する。
例は `samples/math.v1.json`。

## トップレベル

| キー | 必須 | 内容 |
| --- | --- | --- |
| `schemaVersion` | ○ | `1` |
| `id` | ○ | ツリーの ID |
| `title` | ○ | 表示名 |
| `description` |  | 説明 |
| `authors` |  | 作成者の表示名 |
| `sources` |  | 取り込み元のツリー `{ treeId, title?, note? }` |
| `nodes` | ○ | ノード |
| `relations` | ○ | 関係（前提・関連） |
| `achievements` | ○ | 実績の定義 |

## ノード

```json
{ "id": "derivative", "kind": "skill", "parentId": "analysis", "title": "微分",
  "summary": "瞬間の変化率を求める。", "unlocks": "最大・最小を探し、変化の速さを予測できる。" }
```

- `kind`: `group`（分野。内部にグラフを持つ）か `skill`。
- `parentId`: 包含の親。`null` は最上位。親は `group` でなければならず、包含は循環しない。
- `unlocks`: 「何ができるようになるか」。
- `origin`: 取り込んだノードの出典 `{ treeId, nodeId, treeTitle? }`。何度取り込み直しても最初の出典を保つ。
- 空の分野、説明のないノードはそのまま有効。到達点だけ先に置き、途中を後から埋められる。

包含は単一の親とし、別の枝とのつながりは関係で表す。
サンプルでは「勾配（数学›解析学›多変数解析）→ 勾配降下法（機械学習）」のように、分野をまたぐ依存をすべて関係で表せた。
表示ではこれを選択時のポータルと説明パネルの「つながり」に出す。複数の親を持たせる必要がある例は、まだ見つかっていない。

## 関係

```json
{ "id": "r-grad-gd", "type": "prerequisite", "from": "gradient", "to": "gd", "note": "勾配降下法の「勾配」そのもの" }
```

- `prerequisite`: `from` が `to` の前提。学習の案内として扱い、ロックはしない。循環は警告にとどめる。
- `related`: 方向を持たない関連。循環してよい。配置（ELK の層）には使わない。
- `external`: 部分書き出しで、枝の外にある端点を参照として残したもの `{ treeId, title?, path? }`。
  この関係は片方の端点がツリー内に存在しなくてよい。取り込み時、相手が見つからなければ取り込まず報告する。

## 実績

```json
{ "id": "a-calc-100", "title": "微分積分の演習100問", "skillIds": ["derivative", "integral"],
  "condition": { "kind": "text", "text": "微分・積分の演習問題を合計100問解いた" } }
```

実績はノードとは別のデータで、スキルと多対多でつながる。実績の達成からスキルの習得を自動では判定しない。
条件は今のところ説明文（`kind: "text"`）だけ。累計時間・点数・回数・組み合わせは `kind` を増やして表す。
任意のコードを条件に埋め込む形式は採らない。

## 検証

読み込み時に、スキーマ、ID の重複（ノード・関係・実績をまたいで）、存在しない親や端点、
分野でない親、包含の循環、自己参照を検出してエラーにする。
前提の循環と、実績の対象スキルの欠落は警告にする。ファイルは 5MB、ノードは 5000 件までに制限する。
説明文はプレーンテキストとして表示し、HTML として解釈しない。

## 取り込みと部分書き出し

- 取り込みは、元のツリーを変えないコピー。ID が衝突したら `-2` などを付けて付け替え、親子・関係・実績の参照も書き換える。
- 取り込む枝の外とつながる関係は、相手が以前に取り込んだノードとして既にあればつなぎ直し、なければ取り込まずに一覧で報告する。
- 枝だけを書き出すとき、枝の外とつながる関係を「外部参照として残す」か「削除する」かを選び、対象の関係を一覧で示す。
- 取り込み元の更新を自動で反映する仕組みや、別々のツリーの同じスキルを同一視する仕組みはない。
